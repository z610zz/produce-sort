# 果蔬分拣（Three.js）

一个「拿起 / 放下 / 凑满四个就发车」的分类消除小游戏，超市果蔬主题，纯前端、无构建步骤。

这个文件夹是自包含的：three.js 和字体都在 `vendor/` 里，**断网也能跑**。

---

## 怎么运行

### 最省事：双击 `启动游戏.command`

会自动起一个本地服务器并打开浏览器。关闭游戏就回到弹出的终端窗口按 `Control-C`，或者直接关掉那个窗口（服务器会跟着退出，不留后台进程）。

> 第一次双击如果 macOS 拦下来了，右键点它 →「打开」→ 再点「打开」。
> 或者在终端里执行一次 `chmod +x 启动游戏.command`。

### 或者：手动起服务器

```bash
cd produce-sort
python3 -m http.server 8787
```

然后浏览器打开 <http://127.0.0.1:8787/index.html>

> 端口随便挑一个没被占的。**别用 8765** —— 这台机器上 Cocos Creator 的 MCP 服务占着它。
> `启动游戏.command` 会自动从 8765 往后找空端口，所以双击那个不用操心这件事。

**为什么必须过服务器？** 游戏用的是 ES Module 和 `fetch` 读关卡数据，浏览器不允许从 `file://` 加载这两样。直接双击 `index.html` 会白屏。

### 直接跳关

在地址后面加 `?level=` 就行，比如 <http://127.0.0.1:8787/index.html?level=116>（13 辆购物车的最密盘面）。
也可以用左上角的关号输入框。

## 游戏规则

- **拿起**：购物车顶部**连续同种**的果蔬；遇到还没打开的神秘纸袋就截断
- **放下**：空车，或者顶部是同种且没装满的车
- **容量**：每车 4 个；凑齐 4 个相同 → 自动推走
- **盖布**：被盖住的车，推走**对应果蔬**的一车才会掀开；掀开后可能连锁推走
- **单向车**：果蔬只能放进去、拿不出来，装满 4 个同种才会推走
- **神秘纸袋**：头上没东西压着时才打开，打开前不参与拿取
- **通关**：所有果蔬清完 → 购物车依次推走 → 货车关上后备箱、从上方开走 → 通关弹窗

关卡规模：2–13 辆购物车，10 种果蔬。78 关含单向车，119 关含盖布，172 关含神秘纸袋。

## 美术与动画

- **消除元素**：10 种低模果蔬（苹果 / 香蕉 / 胡萝卜 / 西兰花 / 葡萄 / 蓝莓 / 茄子 / 草莓 / 蘑菇 / 青柠），
  241–600 三角形，平均约 360。每种都是「独有颜色 ＋ 独有俯视轮廓」，因为超过六种之后光靠颜色分不开。
- **容器**：购物车。相机接近垂直俯视，推手和轮子在这个角度基本看不见，所以辨识度靠
  **车篮向车尾张开的梯形轮廓**、**横向铁丝栏**、**探出车身的脚轮**来承载。
- **上方载具**：货车。车厢**故意不封顶** —— 俯视下封顶车厢只会是一块盖板，后备箱开合完全看不出来；
  敞篷才能看见车上装的货，以及尾板放平的过程。尾板用浅色、车身用绿色，避免开合时同色糊在一起。
- **开场**：货车从上方倒车进场 → 尾板放下 → 果蔬抛物线飞进各辆购物车。点屏幕可跳过。
- **通关**：购物车依次推走 → 货车收起尾板 → 向上开出画面 → 弹窗。
- **搬运**：一次移动里的每个果蔬都沿抛物线飞到目标车，逐个错开 45ms，全程约 300ms。
  飞行期间 `state.busy` 为真，盘面锁住 —— 否则第二次点击会在果蔬还在空中时改动数据。
  写自动化脚本点击时要等 `!state.busy`，不能用固定延时。

改美术时注意：`produce.js` 里每个模型按自己的自然尺寸建，再由 `makeProduce` 统一适配到同一个装格
（`CELL_W` × `CELL_D`）。适配用的是**两个方向各取其小**，不是按最长边等比缩放 —— 按最长边缩放会把
胡萝卜、香蕉这种细长的压得比苹果小一圈，一列混装摆出来视觉分量对不齐。

## 关卡数据是怎么来的

`levels.json` 不是手写的，是从一份 Unity Addressables bundle 导出后转换来的。
三个脚本在 `关卡数据管线/`，需要 UnityPy（`pip install UnityPy`）和 bundle 文件本身
（不在本仓库内，路径写在 `dump_levels.py` 顶部）：

```bash
python3 dump_levels.py        # 解 bundle -> levels_raw.json（404 个关卡资产）
python3 export_levels.py      # 取主线 Level_1..200_V1 -> levels.json
python3 verify_cover_rule.py  # 穷举验证盖布规则（可选，很慢）
```

导出字段与游戏内字段的对应关系（已逐条核对）：

| 导出字段 | 含义 | 游戏内 |
| --- | --- | --- |
| `items[]` | 果蔬栈，**索引 0 是栈顶**，空槽排在数组前面 | `slots`（反转成索引 0 为车尾底部）|
| `hiddenIndices[]` | 神秘纸袋，索引 0 从不出现在其中 | `hidden` |
| `isStuck` | 单向车 | `stuck` |
| `uncoverRequirement` | **果蔬类型 id**，推走该类型即掀开盖布（0 = 无盖布）| `cover` |

`uncoverRequirement` 是**果蔬类型**而不是「发车计数」，这点有两条独立证据：
闭包可达性上，按类型解释 119 个有盖布关卡全部可达，按发车计数只有 29 关；
穷举求解则**证明**按发车计数解释会有 42 关无解。关卡自带 `generationShuffles`，
说明是从已解状态倒着洗牌生成的，按设计必然可解，所以发车计数那个解释被排除。

## 校验脚本

```bash
cd tools

# 关卡结构校验 + 贪心试解，不需要装任何东西
node solve.mjs

# 用真实 UI 验证神秘纸袋 / 盖布 / 单向车，并遍历 200 关
# 需要先装 playwright，并且游戏服务器正在运行
npm i playwright
node verify.mjs 8787        # 参数是游戏服务器的端口
```

`solve.mjs` 的贪心解法能跑完 129/200。**这不代表剩下 71 关无解**——
求解器看不穿神秘纸袋而已；它真正要拦的是结构性死局（比如永远掀不开的盖布），目前 0 例。

`verify.mjs` 共 11 项检查，全部通过。
